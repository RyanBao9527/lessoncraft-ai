# 01_Python猜数字游戏
先用最终作品建立期待，不展开知识定义。请学生说说今天这个程序需要解决什么问题。接下来先体验一次只允许猜一次的版本。

---

# 02_情境导入
先描述第一次猜错后游戏结束的体验冲突，让学生提出“重复”的需求。运行一次只能猜一次的版本，并追问程序怎样回到输入的位置。接下来把学生的想法整理成课程挑战。

---

# 03_课程挑战
把学习目标说明成允许重复输入、给出大小提示、猜中后停止并祝贺这三个作品标准。请学生思考完成后要用哪三种输入测试游戏。接下来找出我们已经会用的工具。

---

# 04_旧工具够用吗
快速激活变量、input 和 if，不重新讲授旧知识。请学生判断哪一个工具只能判断一次，并指出当前仍缺少重复判断。接下来认识负责“重复”的新工具。

---

# 05_while循环概念
while 循环在条件为 True 时重复执行一组代码，并在每轮开始前重新判断条件。请学生思考条件变成 False 后程序会去哪里。不要把 while 解释成固定重复次数，接下来用流程连接判断和重复。

---

# 06_循环流程
沿着判断条件、执行缩进代码、回到条件再次判断的顺序指读一遍。用手指沿流程走一圈，并请学生预测条件连续三次为 True 时循环体会执行几次。接下来把流程变成全班可参与的循环。

---

# 07_人体while循环
先宣布人体循环规则，再开始动作。请两名学生分别扮演条件与循环体，并在结束后追问为什么这一轮停下。接下来把刚才的动作规则写成最小代码。

---

# 08_最小代码
逐行观察 CODE-01，重点看 guess 每轮更新，以及 guess 等于 answer 后条件如何变为 False。请学生指出哪一行让条件有机会变成 False，并提醒 input 必须位于循环体内。接下来先不运行，预测不同输入会走几轮。

---

# 09_运行前先预测
先收集学生对输入三和七时循环执行次数的预测，再运行同一份 Blueprint 代码验证。不要直接公布答案，让学生用 True 和 False 的变化解释结果。接下来在最小循环中加入大小提示。

---

# 10_互动实践
先明确成功标准，再让学生补全半成品。请学生判断大小判断应该放在 while 的里面还是外面，并只演示缩进位置，不提供新的代码版本。接下来在动手前诊断常见错误。

---

# 11_调试挑战
让学生先说出检查条件、缩进和变量更新的诊断顺序，不直接替学生修改代码。演示手动终止后再定位错误，避免让无法安全终止的死循环运行太久。接下来带着调试清单完成完整项目。

---

# 12_完整版本
输入和大小判断都位于循环体内，所以每次猜测后都会得到反馈并继续判断。运行 CODE-02 的偏小、偏大和正确三类测试输入，请学生说明完整代码怎样满足三个作品标准。保持 Blueprint 原始代码，不现场改写另一个版本。

---

# 13_学生动手
学生独立完成作品时，用完成标准巡视，不逐行替学生写代码。请同伴输入偏小、偏大和正确三类测试数据，并让学生用测试证据说明游戏能正确停止。接下来用测试证据回到本课核心结论。

---

# 14_课堂总结
先让学生复述，再显示标准术语。请学生用一句话说明 while 循环何时继续、何时停止，不要把总结变成重新讲一遍整节课。最后选择一个挑战继续升级作品。

---

# 15_课后挑战
只说明增加猜测次数统计的任务和验收标准，不在课堂末尾给出完整答案。请学生说说准备先修改哪一部分。课程结束后保存作品与测试记录。
